## 4. Как ревьюить мой код

Когда я прошу проверить, сначала запусти `cargo check`, `cargo clippy` и (если есть) `cargo test`, затем прочитай изменённые файлы (`git diff`).

Порядок замечаний:
1. Компилируется ли, правильно ли работает.
2. Владение и заимствования, паники (`unwrap`/`expect` там, где нельзя), гонки и дедлоки.
3. Идиоматичность Rust (стиль clippy).
4. Архитектура, разделение на модули, читаемость, имена.
5. Производительность — только там, где важно (аудиопоток, сканирование библиотеки).

Для каждого замечания: **файл и строка → что не так → почему → наводящая подсказка**. Без исправленного кода.
Обязательно отмечай, что сделано хорошо.

## 5. О проекте

Аудиоплеер. Сначала desktop, потом мобильные платформы. Код лежит на GitHub. Сначала делаю для себя, **позже планирую опубликовать**.

### Возможности
1. **Локальные файлы:** mp3, flac, ogg/opus, wav, m4a/aac; библиотека, теги, обложки, поиск, плейлисты, очередь.
2. **Стриминговые сервисы в одном плеере:** Яндекс Музыка, Spotify, Apple Music/iTunes, YouTube (Music), SoundCloud.
3. **Кастомизация:**
   - внешний вид: темы (цвета, шрифты), раскладка интерфейса, горячие клавиши;
   - звук: эквалайзер, громкость с нормализацией (ReplayGain), gapless, crossfade, возможно DSP-эффекты.
   - Плагинов пока **не** будет (не усложняй архитектуру ради них).

### Архитектурные принципы
- **Cargo workspace:** `core` — чистая библиотека без UI (декодирование, воспроизведение, очередь, библиотека, настройки, DSP); `desktop` — UI для ПК; позже `mobile`. Ядро должно переиспользоваться на мобильных без переписывания.
- **Источники музыки** — общий трейт (поиск, получение трека, плейлисты, авторизация); каждый сервис в отдельном модуле, включается через cargo features.
- **Реальное время:** в аудио-колбэке никаких аллокаций, блокирующих мьютексов, файлового и сетевого I/O. Обмен с остальной программой — через каналы и lock-free очереди. Объясни мне, почему это важно, когда дойдём до этого.
- **Настройки и темы** — в файлах (TOML/JSON), чтобы их можно было править и делиться ими.
- **Ошибки:** `thiserror` в библиотеке, `anyhow` в приложении.

### Платформы — важно помнить
- Разработка идёт на Windows. **Сборка под iOS требует macOS и Xcode**, поэтому мобильную часть сначала делаем под **Android (эмулятор)**, а iOS — когда появится Mac или облачная macOS-сборка в CI. Напомни мне об этом, когда дойдём до мобильных платформ.
- Выбор UI-фреймворка учитывает мобильные платформы. Когда дойдём до этапа 4, сравни со мной актуальные варианты (Tauri 2, Slint, Dioxus, egui, Iced, Flutter + flutter_rust_bridge): поддержка Android/iOS, порог входа для новичка, насколько хорошо поддаются темизации, зрелость. Решение принимаю я.

### Стриминговые сервисы — юридическая честность
Так как плеер будет опубликован:
- перед каждым сервисом проверяй (поиском в сети, если доступен) **актуальные** условия API: есть ли официальный доступ к аудиопотоку, нужна ли премиум-подписка, есть ли DRM, разрешено ли использование в публичном приложении;
- чётко разделяй **официальные** интеграции (API, SDK, управление официальным клиентом, импорт плейлистов) и **неофициальные** (обратная разработка, обход ограничений), объясняй риски вторых (блокировка аккаунта, удаление приложения, претензии правообладателей);

## 6. План (roadmap)

Для каждого этапа: цель → какие концепции Rust понадобятся → подзадачи → критерий «готово».

- **Этап 0. Подготовка.** Установка Rust на Windows (rustup, MSVC Build Tools), rust-analyzer в редакторе, git, репозиторий на GitHub, `.gitignore`, лицензия. Основы языка на мини-задачах вне проекта (The Rust Book, главы 1–10, Rustlings).
- **Этап 1. CLI-плеер.** Проиграть один локальный файл из командной строки (изучить symphonia + cpal или rodio и решить вместе, с чего начать).
- **Этап 2. Управление воспроизведением.** Пауза, перемотка, громкость, очередь, следующий/предыдущий трек; потоки, каналы, `Arc`/`Mutex` и почему их нельзя в аудио-колбэке.
- **Этап 3. Библиотека.** Сканирование папок, чтение тегов и обложек, база данных (SQLite), поиск, плейлисты.
- **Этап 4. GUI на desktop.** Выбор фреймворка, основной интерфейс, связь UI ↔ core.
- **Этап 5. Кастомизация.** Система тем, раскладка, горячие клавиши, эквалайзер и аудионастройки, сохранение настроек.
- **Этап 6. Стриминговые сервисы.** По одному, начиная с самого легально доступного; общий трейт источника, авторизация (OAuth), безопасное хранение токенов.
- **Этап 7. Мобильные платформы.** Сначала Android, затем iOS (нужна macOS).
- **Этап 8. Публикация.** Сборки и релизы через GitHub Actions, README, скриншоты, проверка лицензий.

По ходу учи меня хорошим практикам: маленькие осмысленные коммиты, ветки, тесты, `cargo fmt` и `cargo clippy` перед коммитом, CI.
